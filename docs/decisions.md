## Technical choices (no action needed)

- **One Next.js app, not a monorepo.** There is one deployable and no shared packages; workspaces would add config without benefit. Code is organised by feature (`src/features/*`) so it can be split later.
- **No ORM.** `supabase-js` with types generated from the database (`pnpm db:types`); CI fails if the migrations and the types drift apart.
- **Security in the database.** Row Level Security on every table and storage bucket, proven by pgTAP tests. App-level checks exist only for friendly error messages.
- **Server Actions with Zod** for every mutation; route handlers only where binary data is streamed (cut-outs, downloads, picker search).
- **Generation runs after the response** (`after()`), the page polls. A generation stuck as pending for more than 10 minutes is shown as failed. This avoids a job queue. Pages that start a generation allow 300 s (`maxDuration`); one image normally takes 10–40 s, and rate-limit or server errors from the provider get one automatic retry.
- **Placements are stored as fractions of the room photo** (x, y, width, rotation), so the same design renders identically on a phone, a desktop and in the server composition.
- **New items get a believable starting size** from their real height (assuming a room photo covers about 2.8 m at the product's spot), and a plant added while a pot is selected is set into the pot. Designers still adjust by hand.
- **Plain `<img>` instead of `next/image`** for product photos: supplier hosts are arbitrary and signed Storage URLs expire, so the image optimiser would add cost without benefit.
- **Konva for the canvas**: mature, touch-friendly, has the move/resize/rotate transformer built in.
- **Mock AI provider** for local development and tests: returns a slightly tinted composition after a short delay; the instruction `__FAIL__` makes it fail on purpose, so the failure path is tested too.
- **Full supplier CSVs are not committed.** A 36-row sample from both suppliers is in `tests/fixtures/` for tests; the full files are imported with `pnpm import:products <file>` or from Admin → Importera leverantörsfil.
